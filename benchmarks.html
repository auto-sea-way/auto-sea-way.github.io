Benchmarks

This page has every number behind the comparison on the front page, the method, and the speed benchmark of auto-sea-way.

On this page: method, per route, speed of auto-sea-way, raw data.

The test ran on 5 November 2026 on a Mac mini (Apple M2, 8 GB, macOS), one router at a time. @arcnautical/maritime-routing was added on 6 November 2026 and ran on the same machine with the same routes and scripts. Every router got the same 45 routes: the 23 routes of the auto-sea-way benchmark and 22 port pairs from NGA Pub 151, Distances Between Ports (11th edition). If you find a mistake, please open an issue.

Method

  • Same input. Each router got the start and end coordinates of all 45 routes, with the settings listed below. Where a router has a choice of network, we used its finest one.
  • Shore buffer. auto-sea-way ran with shore_buffer=1.0: it keeps 1 nm off the coast where the water allows it, so its routes are a little longer and closer to the tracks that boats sail. This is not its default. The other routers have no such option and ran with their defaults.
  • Length. We measured the line that each router returned with one formula for all: the haversine distance between the points, with an earth radius of 3,440.065 nm. Where a line starts or ends away from the requested point, we added the straight distance to that point. So every length runs from the requested start to the requested end. The numbers that the routers report themselves can differ: auto-sea-way leaves out legs over land in distance_nm, and searoute-ts leaves out the legs to the requested points.
  • Pub 151. The 22 port pairs and their positions are the ones in the reference test of auto-sea-way. They are pairs where the Pub 151 track is a shortest route, so a good router should be close. Pub 151 rounds to whole miles, and its port positions are often a little inland.
  • Over land, OpenStreetMap check. We walked every line along great circles and took a sample every 0.5 nm. A sample is over land when it and four points 0.1 nm to the north, south, east and west of it are all inside the OpenStreetMap land polygons (osmdata.openstreetmap.de, March 2026). The Panama and Kiel canals have locks, so OpenStreetMap maps them as inland water, and the land polygons cover them. Inside the boxes of these two canals, the OpenStreetMap water polygons (lakes, canals and docks, downloaded on 6 November 2026 and kept in method/canal-water/) also count as water. auto-sea-way builds its graph from the same land polygons, so we also ran the second check.
  • Over land, Natural Earth check. The same walk on the Natural Earth 1:10m land, with a sample every 2 nm, and a sample counts only when it is at least 3 nm inside one land polygon. This is the rule of the reference test of auto-sea-way. Natural Earth is coarse, so this check cannot see land that is narrower than about 6 nm.
  • What is not counted. The Natural Earth check skips the samples inside the boxes of the canals and narrow passages of auto-sea-way (Suez, Panama, Kiel, Corinth and 20 others) for every router, because Natural Earth does not show them as water. The OpenStreetMap check skips nothing. 20 of the 45 routes have a requested point that is itself on land, for example a port position in a town. Land within 10 nm of such a point is reported apart in the raw data, because every router has to cross it.
  • Time. We measured each route after one warm-up call, then took the median of 10 runs (3 runs when a route took longer than 1 s). @arcnautical/maritime-routing keeps finished routes in a cache, so we cleared the cache before every call. auto-sea-way ran as asw serve and was called over HTTP on the same machine; the others ran inside their own process. eurostat/searoute only runs batches from the command line, so it has no time per route.
  • Memory. Peak resident memory of the process. For auto-sea-way the 1.43 GB graph is memory-mapped, so the operating system decides how much of it stays in memory.

Settings used

  • auto-sea-way: asw serve, GET /route?from=lat,lon&to=lat,lon&shore_buffer=1.0 (canals open, Arctic routes closed). shore_buffer is not the default; the other routers have no such option and ran with their defaults. Measured over HTTP on the same machine. The HTTP round trip took 0.2 ms.
  • searoute-py: searoute(origin, destination, units='naut', append_orig_dest=True), default restrictions (Northwest Passage closed). Measured in the same Python process.
  • scgraph: GeoGraph.load_geograph('marnet').get_shortest_path(origin, destination), defaults otherwise. It has no option to close the Arctic routes.. Measured in the same Python process.
  • searoute-ts: seaRoute(origin, destination, {network: marnet-20km, appendOriginDestination: true, units: 'nauticalmiles'}). Measured in the same Node.js process.
  • eurostat/searoute: java -jar searoute-jar-3.6.jar -res 5 -kiel 1 -corinth 1 (Kiel and Corinth canals opened to match auto-sea-way; other passages at their defaults). The jar runs a batch of routes. All 45 routes took 9 to 20 s in three runs, and one route alone 1.4 s, most of it Java start-up and network loading.
  • @arcnautical/maritime-routing: findOceanPath(fromLat, fromLon, toLat, toLon), the API for coordinates, with the defaults. Its port API (computeRoute) takes only UN/LOCODE port codes, so it cannot route between our coordinates.. Measured in the same Node.js process on 6 November 2026, with its route cache cleared before every call.

Routers we did not run

  • searoute-js: the npm package was last published in 2022. It is a port of the Eurostat network, the same as searoute-py and searoute-ts.
  • seaRoute (Go): a full application with a web interface, only published as a Docker image. It also uses the Eurostat MARNET network.
  • Commercial routing services are not part of this test.

Raw data and scripts

  • summary.json: every number per router and route, with the settings and versions.
  • data/routes/<route>.json: the line of each router for one route, joined to the requested points, and the parts over land. For example rotterdam-singapore.json.
  • method/: the scripts that ran the routers and measured the lines.

auto-sea-way is open source under the MIT and Apache 2.0 licenses. Source, releases, issues.

Coastlines for the land check: OpenStreetMap land polygons from osmdata.openstreetmap.de (ODbL) and Natural Earth (public domain). Port distances: NGA Pub 151, Distances Between Ports.
